# RenOS Docker Installer

Production-ready Docker deployment for RenOS — your devices, one intelligent system.

## Quick Start

```bash
curl -fsSL https://raw.githubusercontent.com/renos-project/renos/main/installer/docker/run.sh | bash
```

Or clone the repository and run locally:

```bash
git clone https://github.com/renos-project/renos.git
cd renos/installer/docker
chmod +x run.sh
./run.sh
```

The installer will:
1. Check Docker and Docker Compose are installed
2. Generate a `.env` file with secure random secrets
3. Prompt for hostname, admin credentials, and TLS options
4. Build Docker images and start all services
5. Wait for health checks to pass
6. Create the admin user
7. Print the dashboard URL

## Command-Line Flags

| Flag           | Description                                              |
|----------------|----------------------------------------------------------|
| `--dev`        | Development mode: debug logging, self-signed TLS         |
| `--build`      | Force rebuild images from source                         |
| `--pull`       | Pull pre-built images from container registry            |
| `--update`     | Pull latest images, rebuild, recreate changed containers |
| `--uninstall`  | Stop and remove all containers, volumes, images, config  |
| `--help`       | Show usage help                                          |

## Prerequisites

- Docker Engine 24+ (with Compose V2 plugin)
- Linux (x86_64, arm64), macOS, or Windows WSL2
- 4 GB RAM minimum (8 GB recommended)
- 10 GB free disk space
- Ports 80, 443, and 5432 available (or configured differently in `.env`)

## Architecture

```
                     ┌─────────────┐
                     │   Nginx     │  ports 80/443
                     │  (reverse   │  TLS termination
                     │   proxy)    │
                     └──────┬──────┘
                            │
              ┌─────────────┼─────────────┐
              │             │             │
       ┌──────┴──────┐ ┌───┴───────┐ ┌───┴────────┐
       │  RenOS Hub  │ │ RenOS Core│ │ RenOS Agent│
       │  (Next.js)  │ │   (Go)    │ │   (Rust)   │
       │   port 3000 │ │ port 8443 │ │ privileged │
       └──────┬──────┘ └───┬───────┘ └────────────┘
              │            │
              └─────┬──────┘
                    │
         ┌──────────┼──────────┐
         │          │          │
   ┌─────┴─────┐ ┌──┴───┐ ┌───┴────┐
   │PostgreSQL │ │Redis │ │  NATS  │
   │    16     │ │  7   │ │  2.10  │
   └───────────┘ └──────┘ └────────┘
```

- **renos-backend** network (internal): all services communicate over this private bridge
- **renos-frontend** network (external): only Nginx is exposed to the outside world

## Configuration

### Environment Variables

| Variable                  | Required | Default            | Description                                 |
|---------------------------|----------|--------------------|---------------------------------------------|
| `RENOS_HOSTNAME`          | no       | `renos.local`      | Public hostname for the dashboard           |
| `RENOS_HTTP_PORT`         | no       | `80`               | HTTP port for the reverse proxy             |
| `RENOS_HTTPS_PORT`        | no       | `443`              | HTTPS port for the reverse proxy            |
| `POSTGRES_USER`           | no       | `renos`            | PostgreSQL user                             |
| `POSTGRES_PASSWORD`       | **yes**  | —                  | PostgreSQL password (auto-generated)        |
| `POSTGRES_DB`             | no       | `renos`            | PostgreSQL database name                    |
| `REDIS_PASSWORD`          | **yes**  | —                  | Redis password (auto-generated)             |
| `RENOS_EXTERNAL_URL`      | **yes**  | —                  | Public-facing URL of the RenOS instance     |
| `RENOS_PORT`              | no       | `8443`             | Core API port                               |
| `RENOS_GRPC_PORT`         | no       | `8444`             | Core gRPC port (agent communication)        |
| `RENOS_JWT_SECRET`        | **yes**  | —                  | HMAC key for JWT signing (64 hex chars)     |
| `RENOS_ENCRYPTION_KEY`    | **yes**  | —                  | Master encryption key (64 hex chars)        |
| `RENOS_LOG_LEVEL`         | no       | `info`             | Log level: debug, info, warn, error         |
| `RENOS_CA_CERT_DIR`       | no       | `/var/lib/renos/ca`| Directory for CA certificates               |
| `RENOS_ADMIN_EMAIL`       | no       | `admin@renos.local`| Initial admin email                         |
| `RENOS_ADMIN_PASSWORD`    | **yes**  | —                  | Initial admin password                      |
| `RENOS_VERSION`           | no       | `dev`              | Build version tag                           |

Variables marked **yes** are auto-generated by `run.sh` if `.env` does not exist.

### Manual Configuration


## Volume Management

### Named Volumes

| Volume           | Mount Point                    | Purpose                          |
|------------------|--------------------------------|----------------------------------|
| `pgdata`         | `/var/lib/postgresql/data`     | PostgreSQL database files        |
| `redis-data`     | `/data`                        | Redis append-only log + RDB      |
| `nats-data`      | `/data`                        | NATS JetStream data              |
| `renos-data`     | `/var/lib/renos/data`          | Core application data            |
| `renos-ca`       | `/var/lib/renos/ca`            | CA certificates (shared w/ Nginx)|
| `renos-backups`  | `/backups`                     | Database backup storage          |

Inspect volume usage:

```bash
docker volume ls | grep renos
docker volume inspect renos_pgdata
```

### Data Locations

Docker named volumes are stored at `/var/lib/docker/volumes/` on Linux. To back them up:

```bash
# Stop services
docker compose down

# Backup volumes
docker run --rm -v renos_pgdata:/source -v /tmp/backup:/target alpine \
    tar czf /target/pgdata-$(date +%Y%m%d).tar.gz -C /source .

# Restart
docker compose up -d
```

## Backup & Restore

### Quick Database Backup

```bash
# Create a timestamped backup
docker compose exec -T postgres pg_dump -U renos renos | gzip > backup-$(date +%Y%m%d-%H%M%S).sql.gz
```

### Restore Database

```bash
# Stop core
docker compose stop renos-core

# Drop and recreate the database
docker compose exec -T postgres psql -U renos -d postgres \
    -c "DROP DATABASE IF EXISTS renos;" \
    -c "CREATE DATABASE renos OWNER renos;"

# Restore from backup
gunzip -c backup-20250101-120000.sql.gz | \
    docker compose exec -T postgres psql -U renos -d renos --single-transaction

# Restart core
docker compose start renos-core
```

### Automated Backups

Add a cron job for nightly backups:

```bash
# Edit crontab: crontab -e
# Run backup at 2 AM daily
0 2 * * * cd /opt/renos && docker compose exec -T postgres pg_dump -U renos renos | gzip > backups/renos-$(date +\%Y\%m\%d).sql.gz && find backups/ -name "renos-*.sql.gz" -mtime +30 -delete
```

## Upgrading

### Standard Upgrade

```bash
./run.sh --update
```

This pulls the latest Git changes, rebuilds images, and recreates containers. No data is lost.

### Manual Upgrade Steps

```bash
# 1. Pull latest source
git pull origin main

# 2. Rebuild and restart
docker compose build
docker compose up -d

# 3. Verify health
docker compose ps
```

### Database Migrations

Migrations run automatically when Core starts. To run them manually:

```bash
docker compose exec renos-core renos-core migrate
```

## Troubleshooting

### View Logs

```bash
# All services
docker compose logs -f

# Specific service
docker compose logs -f renos-core
docker compose logs -f renos-hub
docker compose logs -f nginx
```

### Service Not Starting

```bash
# Check status of all services
docker compose ps

# Check resource usage
docker stats

# Inspect a service
docker compose logs --tail=50 renos-core

# Restart a single service
docker compose restart renos-core
```

### Port Conflicts

```bash
# Check what is using port 80 or 443
sudo lsof -i :80
sudo lsof -i :443

# Change ports in .env
RENOS_HTTP_PORT=8080
RENOS_HTTPS_PORT=8443
```

### Reset Everything

```bash
./run.sh --uninstall
# Then reinstall with a fresh configuration
./run.sh
```

### Common Issues

| Issue                          | Solution                                                   |
|--------------------------------|------------------------------------------------------------|
| Postgres won't start           | Remove volume: `docker compose rm -v postgres`             |
| Core can't connect to DB       | Check `POSTGRES_PASSWORD` matches in `.env`                |
| Nginx 502 Bad Gateway          | Ensure core and hub are healthy: `docker compose ps`       |
| TLS certificate errors         | Generate new self-signed certs or configure Let's Encrypt  |
| Out of disk space              | Prune Docker: `docker system prune -f`                     |
| Permission denied for volumes  | Ensure host directories have correct ownership             |

## Security

- All internal services are on an isolated `renos-backend` network
- Only Nginx is exposed to the external `renos-frontend` network
- Redis requires authentication via `REDIS_PASSWORD`
- PostgreSQL uses strong passwords (auto-generated)
- JWT secrets and encryption keys are auto-generated with `openssl rand -hex 32`
- Nginx includes security headers (HSTS, CSP, X-Frame-Options, etc.)
- Rate limiting is applied to API and auth endpoints
- The agent runs in privileged mode only for Docker device management

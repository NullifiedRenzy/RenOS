# RenOS v1.1 Polish Initiative — M61–M70 Roadmap

Date: 2026-08-03
Base: RenOS v1.0.0 (feature freeze). This initiative adds **no new major subsystems** —
it hardens, polishes, and professionalizes the existing platform.

Rules: no breaking changes, no regressions, everything tested, production quality. Every
milestone includes: database (if needed), API, frontend, tests, documentation, migration
guide if required, benchmark if performance related.

## M61 — Global Search

**API (new):** `GET /api/v1/search?q=&limit=`
Aggregates across: devices, jobs, workflows, plugins (marketplace + installed), policies,
secrets (names only, no values), users, logs, containers, VMs, clusters. Returns typed
grouped results `{ results: { devices: [...], jobs: [...], ... } }` + `total`.
Search on `name`/`title`/`hostname`/`id` via `ILIKE '%q%'` per repo, UNION per category.

**Frontend:** Ctrl+K / Cmd+K opens the command center. Search tab with fuzzy matching
(lightweight in-repo fuzzy util scoring substring + prefix + typo tolerance), instant
results grouped by category with icons, arrow-key navigation, Enter to navigate, `/` to
focus search. VSCode-like UX.

**Tests:** Go handler + repo tests (match/no-match/case-insensitive/pagination/role);
Vitest for fuzzy util + modal (open/close/keyboard/select).

## M62 — Command Palette

**Frontend:** Second mode of the same command center. Palette entries:
Open Dashboard/Devices/Jobs/Workflows/Plugins/Policies/Vault/Settings, Restart Device,
Run Workflow, Open Terminal, Create Secret, View Logs, Toggle Dark Mode, Copy server
version. Keyboard accessible end-to-end (Ctrl+K open, ↑/↓ navigate, Enter run, Esc close,
`>` prefix switches to command mode).

**Tests:** Vitest for palette command registry + keyboard handling.

## M66 — Notification Center — ✅ COMPLETE

**Database (migration 000049):** `inapp_notifications` table
(id UUID PK, user_id UUID FK→users, title, body, type, entity_type, entity_id,
is_read bool, metadata jsonb, created_at, read_at timestamptz). Index on
(user_id, is_read), (user_id, created_at).

**API:** `GET /api/v1/notifications/inapp?unread=&type=&search=&limit=&offset=`,
`GET /api/v1/notifications/inapp/unread_count`,
`POST /api/v1/notifications/inapp/{id}/read`,
`POST /api/v1/notifications/inapp/read-all`.
Producers wired into existing events: workflow completed, device offline, alert triggered,
AI suggestion, plugin update available, job finished.

**Frontend:** Bell icon in header with unread badge (poll 30s + refetch on focus),
dropdown panel (recent 20, mark-all-read), and `/notifications` page with new Inbox tab
(All/Unread/type filters, search, mark single/all read).

**Tests:** Go notifier + repo; Vitest for bell + inbox tab (filters, mark read, empty state).

**Status:** Done. Inbox tab added to `/notifications` page; OpenAPI spec updated with the
four inapp routes + InAppNotification/UnreadCountResponse schemas; full core + hub test
suites green.

## M65 — Smart Dashboards — ✅ COMPLETE

**API (extends existing):** `GET /api/v1/dashboards/{id}` now returns `widget_data`
(hydrated display data keyed by widget ID) for config-driven widget types:
`device-status`, `cpu`, `memory`, `alerts`, `logs`, `workflows`, `ai-usage`,
`containers`, `proxmox`, `devices-overview`. New `PUT /api/v1/dashboards/{id}`
(metadata + atomic full-widget-set replace) and `DELETE /api/v1/dashboards/widgets/{id}`.
Hydration lives in `internal/api/dashboard_hydrate.go` behind a `widgetDataProvider`
interface (fake-testable).

**Frontend:** Dashboard builder — CSS-grid drag-and-drop + corner resize handles
(pointer events, no new dependency), widget palette, add/remove, save layout to
backend, auto-refresh. Reusable `WidgetGrid` component + `WidgetRenderer` per type.

**Tests:** Go `hydrateDashboardData` tests (keys, omitted failures, nil provider);
Vitest for grid layout utils (move/resize/clamp/next-free-position) + WidgetGrid
(drag disabled in view mode, edit affordances, remove) + WidgetRenderer.

**Status:** Done. Backend + OpenAPI updated (MonitoringWidget schema, new routes);
core build/vet/tests + hub tsc + 41 Vitest tests green.

## M63 — UI Polish — ✅ COMPLETE

Swept every page in `app/(dashboard)/` (7 parallel subagents) using the M70 design system.

- **Dark-mode-only color bug fixed:** 14 pages hard-coded dark-theme Tailwind colors
  (zinc-900 card backgrounds, white/zinc-300/400/500 text) that were illegible in light
  mode. All converted to semantic CSS tokens: `--color-surface-elevated` (cards),
  `--color-surface` (rows/chips), `--color-border(-strong)`, `--color-text-primary/
  secondary/tertiary`, `--color-success/warning/error/info` + tint badges, accent
  primary buttons (`--color-accent`/`--color-accent-hover`/`--color-text-on-accent`).
  Affected: marketplace, updates, deploy, cluster, mobile, iam, developer, plugins,
  monitoring, workflows (+ vault/proxmox/notifications verified already clean).
- **Undefined classes fixed:** `text-body-2` (102 uses) and `text-body-3` were not in
  the Tailwind config and silently generated nothing. Remapped globally:
  `text-body-2` → `text-body-small` (13px), `text-body-3` → `text-caption` (12px).
- **Typography normalized:** page `<h1>` → `text-headline-2 font-semibold`; section
  `text-lg` headings → `text-headline-3`; subtitle text → `text-body-small`.
- Tokenized status-color const maps (statusColors/roleColors/taskStatusColors/severity)
  in-place; `text-white` retained only where it correctly sits on colored
  accent/error/success backgrounds.

**Verification:** `npx tsc --noEmit` clean; 55 Vitest tests pass; `next build` passes
(33 static pages); Storybook build passes. Zero remaining zinc/white hardcoded classes
in `app/` or `components/`.

**Status:** Done.

## M68 — Accessibility — ✅ COMPLETE

WCAG AAA where practical.

- **Automated axe checks (new):** installed `axe-core@4.13`; added
  `components/ui/a11y.test.tsx` — 8 axe-based tests over Button, Input (label/error),
  Select, Badge, Tabs, Dialog, Table (scope), SkipLink using semantic/structure rules
  (aria-*, button-name, label, nested-interactive, heading-order, scope-attr-valid…).
  All pass.
- **Raw modals upgraded:** every remaining hand-rolled modal (docker action output,
  proxmox confirm, plugins remove, iam modal, device-containers, device-file-browser
  rename/new-folder/preview, process-manager confirm) now renders `role="dialog"`,
  `aria-modal="true"`, an accessible `aria-label`, plus a new shared
  `hooks/use-dialog.ts` (Esc-to-close, focus into dialog on open, focus restore to
  trigger on close). `hooks/use-dialog.test.tsx` — 3 tests (semantics, Esc, focus).
- **Tables:** all 181 `<th>` headers now carry `scope="col"`; the sortable header in
  process-manager also got `aria-sort` + keyboard sort (Enter/Space).
- **Keyboard navigation:** clickable dashboard cards on Monitoring became real
  `<button>`s; focus-visible rings were already global; skip link, focus-trap Dialog,
  arrow-key Tabs, and Ctrl+K command center were already present and confirmed.
- **Color-independent status:** cluster nodes status column (color-only dot) now pairs
  the dot with an `sr-only` status label; decorative dots remain `aria-hidden`.
- **High-contrast support:** `prefers-contrast: more` override block in
  `styles/tokens.css` strengthens borders, text tiers, focus ring, and overlay in both
  light and dark mode.
- **Undefined classes fixed (M63 follow-through):** `text-body-1` (→`text-body`),
  `text-body-4` (→`text-caption`), `text-title-2`/`text-title-3`

  (→`text-headline-4`) were silently generating nothing. Repo-wide zero remaining

**Verification:** `tsc` clean; 66 Vitest tests pass (9 files, +11 new a11y/hook tests);
`next build` passes (33 pages); Storybook build passes.

**Status:** Done.

# Upgrade: v0.2.0 → v0.3.0

**Release date:** 2026-06-01

## Summary

v0.3.0 introduces major new subsystems: AI (RenAI), monitoring and alerts,
vault secrets management, notifications, identity provider integration
(OIDC/OAuth2/LDAP), the marketplace framework, mobile platform support,
and webhook developer platform. This release includes significant database
schema changes and a v2 SDK with new API endpoints.

## Breaking Changes

### 1. Database: Major schema expansion

12 new tables were added and 5 existing tables were modified with NOT NULL
constraints and foreign key changes.

### 2. SDK: v1 → v2

The Go, TypeScript, and Python SDKs were restructured. The `Client` class
was renamed and method signatures changed.

**Before (v0.2.0 — Go):**
```go
client := renos.NewClient("http://localhost:8443", token)
devices, err := client.ListDevices()
```

**After (v0.3.0 — Go):**
```go
client, err := renossdk.NewClientFromLogin("http://localhost:8443", email, password)
devices, err := client.ListDevices(1, 50)  // pagination required
```

**Before (v0.2.0 — Python):**
```python
client = RenOS("http://localhost:8443", api_key="...")
devices = client.get_devices()
```

**After (v0.3.0 — Python):**
```python
from renos import RenOSClient
client = RenOSClient.login("http://localhost:8443", "admin@renos.local", "password")
devices = client.list_devices(page=1, per_page=50)
```

### 3. API: Pagination required on list endpoints

All list endpoints now require `page` and `per_page` parameters. Unlimited
listing is no longer supported. Maximum `per_page` is 200.

### 4. API: Unified JSON envelope

All responses now use a consistent envelope format:

**Before (v0.2.0):**
```json
[
  {"id": "1", "name": "device-01"}
]
```

**After (v0.3.0):**
```json
{
  "data": [{"id": "1", "name": "device-01"}],
  "total": 1,
  "page": 1,
  "per_page": 50
}
```

For single resources, `data` wraps the object directly.

### 5. Configuration: New required variables

**New required:**
- `RENOS_REDIS_URL` (was optional, now required for sessions and rate limiting)
- `RENOS_EXTERNAL_URL` (required for OIDC redirect URIs and webhook callbacks)

**New optional with defaults:**
- `RENOS_LOG_LEVEL` (default: `info`)
- `RENOS_AGENT_HEARTBEAT_INTERVAL` (default: `30`)
- `RENOS_AGENT_OFFLINE_TIMEOUT` (default: `90`)

### 6. Agent: mTLS required

Agent-to-Core communication now requires mTLS. Self-signed certificates
are auto-generated by the installer, but existing agents must re-enroll.

### 7. Plugin permissions: Granular scoping

Plugin permissions now support device-scoped restrictions:

**Before:**
```json
"permissions": ["devices:exec"]
```

**After:**
```json
"permissions": ["devices:exec:web-01", "devices:exec:db-01"]
```

Use `devices:exec:*` for all devices (requires admin approval).

## Step-by-Step Migration

### Step 1: Pre-migration checks

```bash
# Check current version
renos version
# Must be v0.2.x

# Backup everything
./scripts/backup.sh
cp .env .env.v0.2.0
mkdir -p /tmp/renos-v0.2-backup
cp -r /etc/renos /tmp/renos-v0.2-backup/
```

### Step 2: Update configuration

```bash
# Add new required variables
echo "RENOS_REDIS_URL=redis://localhost:6379/0" >> .env
echo "RENOS_EXTERNAL_URL=https://renos.yourdomain.com" >> .env

# Verify JWT secret is strong enough (min 32 chars)
if [ ${#RENOS_JWT_SECRET} -lt 32 ]; then
  echo "RENOS_JWT_SECRET=$(openssl rand -base64 48)" >> .env
fi
```

### Step 3: Pull new images

```bash
docker compose -f docker-compose.prod.yml pull
```

### Step 4: Run database migrations

```bash
docker compose up -d postgres redis nats
cd core && go run ./cmd/renos-core/ migrate
```

Expected migrations:

| Migration ID | Description |
|---|---|
| `008_create_ai_tables` | AI conversations, providers, prompts |
| `009_create_monitoring_tables` | Metrics, alert rules, alert instances |
| `010_create_vault_tables` | Secrets, keys, policies, grants |
| `011_create_notification_tables` | Notification providers, templates |
| `012_create_identity_providers` | OIDC/OAuth2/LDAP provider configs |
| `013_create_webhook_tables` | Webhook subscriptions, delivery logs |
| `014_create_marketplace_tables` | Plugin listings, reviews |
| `015_create_mobile_tables` | Push tokens, mobile sessions |
| `016_alter_devices_add_tags` | Tags JSONB column for device tagging |
| `017_alter_plugins_permissions` | Permission scope expansion |

### Step 5: Regenerate TLS certificates

```bash
docker compose up -d core
./renctl ca rotate --force
```

### Step 6: Update SDK dependencies

**Go:**
```bash
cd your-project
go get github.com/renos-project/renos/sdk/go@v0.3.0
```

**TypeScript:**
```bash
npm install @renos/sdk@^0.3.0
```

**Python:**
```bash
pip install --upgrade renos-sdk>=0.3.0
```

### Step 7: Reinstall plugins with new permissions

```bash
renos plugins:list --format json | jq -r '.[].name' | while read name; do
  renos plugins:uninstall "$name"
  renos plugins:install "./plugins/$name/plugin.json"
  renos plugins:enable "$name"
done
```

### Step 8: Re-enroll agents with mTLS

```bash
# On each agent
sudo renos-agent unenroll
sudo renos-agent enroll --server https://renos.yourdomain.com:8443 \
  --token $(renctl enroll-token create --label "agent-upgrade" --expires-in 1h)
```

## Database Migration

Key schema changes:

- **New tables (12):** `ai_conversations`, `alert_rules`, `alert_instances`, `secrets`, `notification_providers`, `identity_providers`, `oauth2_apps`, `api_tokens`, `webhooks`, `webhook_deliveries`, `marketplace_listings`, `mobile_devices`
- **Modified tables (5):** `devices` (added `tags` JSONB), `plugins` (permission scope), `users` (added `avatar_url`), `sessions` (added `device_info`), `workflow_runs` (added `trigger_type`)
- **Indexes added:** 8 new indexes for query performance

Migration is additive (no destructive column drops). Rollback requires
full database restore.

## Rollback Procedure

```bash
# Stop services
docker compose -f docker-compose.prod.yml down

# Restore database (destructive — v0.3.0 migrations cannot be reverted)
./scripts/restore.sh backups/renos-backup-<pre-upgrade-date>.sql.gz

# Restore config
cp .env.v0.2.0 .env
cp -r /tmp/renos-v0.2-backup/* /etc/renos/

# Restore v0.2.0 images
docker compose -f docker-compose.prod.yml up -d
```

## Verification

```bash
# 1. Core health
curl http://localhost:8443/api/v1/healthz
# Expected: {"status":"ok"}

# 2. Login and get token
TOKEN=$(curl -s -X POST http://localhost:8443/api/v1/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"email":"admin@renos.local","password":"admin"}' | jq -r '.token')

# 3. Paginated device list
curl -s -H "Authorization: Bearer $TOKEN" \
  "http://localhost:8443/api/v1/devices?page=1&per_page=10" | jq '.data | length'
# Expected: number of devices (may be 0)

# 4. Unified JSON envelope
curl -s -H "Authorization: Bearer $TOKEN" \
  "http://localhost:8443/api/v1/version" | jq '.data'
# Expected: {"version":"0.3.0","commit":"...","build_time":"..."}

# 5. AI system
curl -s -H "Authorization: Bearer $TOKEN" \
  "http://localhost:8443/api/v1/ai/settings" | jq '.data'
# Expected: AI configuration object

# 6. Monitoring
curl -s -H "Authorization: Bearer $TOKEN" \
  "http://localhost:8443/api/v1/alerts/active" | jq '.total'
# Expected: integer (0 or more)

# 7. Vault
curl -s -H "Authorization: Bearer $TOKEN" \
  "http://localhost:8443/api/v1/vault/secrets" | jq '.total'
# Expected: integer

# 8. Agent mTLS
curl -s --cert /etc/renos/ca/certs/agent.crt \
  --key /etc/renos/ca/keys/agent.key \
  "https://localhost:8443/api/v1/healthz"
# Expected: {"status":"ok"}

# 9. Webhook system
curl -s -H "Authorization: Bearer $TOKEN" \
  "http://localhost:8443/api/v1/webhooks" | jq '.total'
# Expected: integer
```

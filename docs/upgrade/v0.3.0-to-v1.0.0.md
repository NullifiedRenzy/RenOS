# Upgrade: v0.3.0 → v1.0.0

**Release date:** 2026-07-28

## Summary

v1.0.0 is the first stable production release. It includes security hardening
(M56, S1-S24), performance optimizations (P1-P8), and production reliability
features including chaos engineering validation, circuit breakers, rate
limiting with bounded maps, and comprehensive test coverage.

This upgrade has **significant breaking changes** to security, configuration,
and API behavior. Plan for a maintenance window of 2-4 hours.

## Breaking Changes

### 1. Security: CSP hardened — inline scripts blocked

Content Security Policy now blocks `unsafe-inline` and `unsafe-eval`.
Custom hub extensions using inline scripts will break.

**Before (v0.3.0):**
```html
<script>
  console.log("hello");
</script>
```

**After (v1.0.0):**
```html
<script src="/plugins/my-plugin/script.js"></script>
<!-- Or use nonce-based approach -->
<script nonce="<generated-nonce>">
  console.log("hello");
</script>
```

### 2. Security: CSRF protection enforced

All POST/PUT/PATCH/DELETE requests must include `Origin`, `X-Requested-With`,
or `Authorization` header. Agent endpoints are exempt.

**Before (v0.3.0):**
```bash
curl -X POST http://localhost:8443/api/v1/devices/abc/commands \
  -H 'Content-Type: application/json' \
  -d '{"command":"uptime"}'
```

**After (v1.0.0):**
```bash
curl -X POST http://localhost:8443/api/v1/devices/abc/commands \
  -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"command":"uptime"}'
```

### 3. Security: SQL injection fixes — webhooks use parameterized queries

Custom webhook scripts that used string concatenation for SQL will break.

**Before (v0.3.0):**
```go
query := fmt.Sprintf("INSERT INTO webhook_logs (payload) VALUES ('%s')", payload)
```

**After (v1.0.0):**
```go
query := "INSERT INTO webhook_logs (payload) VALUES ($1)"
db.Exec(query, json.Marshal(payload))
```

### 4. Security: Error messages sanitized

Error responses no longer leak internal paths, database error details, or
connection information.

**Before (v0.3.0):**
```json
{
  "error": "pq: relation \"devices\" does not exist at /go/src/renos/internal/db/query.go:142"
}
```

**After (v1.0.0):**
```json
{
  "code": "DB_ERROR",
  "message": "An internal error occurred"
}
```

### 5. Security: Token generation uses crypto/rand

Custom terminal/plugin code that relied on `math/rand` for token generation
will produce predictable tokens and trigger security warnings.

**Before (v0.3.0):**
```go
token := fmt.Sprintf("%x", rand.Uint64())
```

**After (v1.0.0):**
```go
b := make([]byte, 32)
crypto/rand.Read(b)
token := hex.EncodeToString(b)
```

### 6. API: Pagination limits enforced

- `per_page` capped at 200 (was unbounded)
- `offset` capped at 10,000 (was unbounded)
- Exceeding limits returns HTTP 400

### 7. API: Method override restricted

`X-HTTP-Method-Override` now only allows: GET, HEAD, OPTIONS.
Overriding to POST/PUT/DELETE is blocked.

### 8. Configuration: Secrets validation on startup

RenOS now validates all secrets on startup and refuses to start if:
- JWT secret is empty or < 32 characters
- Encryption key is empty or < 32 characters
- Admin password uses default value (checked in production mode)

### 9. Agent: Command policy enforcement

The agent now blocks destructive commands including `rm -rf /`, `mkfs`,
fork bombs, and similar patterns. Custom automation that relied on these
will fail.

### 10. WebSocket: Origin restrictions

WebSocket connections must have `Origin` header matching `localhost:PORT`.
The wildcard `.renos.local` is no longer accepted.

## Step-by-Step Migration

### Step 1: Backup and pre-checks

```bash
# Full backup
./scripts/backup.sh
cp .env .env.v0.3.0

# Check for deprecated patterns
./renctl audit security --level critical
# Fix any issues found before proceeding

# Check current version
renos version
# Must be v0.3.x
```

### Step 2: Audit your custom code

```bash
# Check for math/rand usage in token generation
grep -r "math/rand" core/ plugins/ --include="*.go"

# Check for inline scripts in hub extensions
grep -r "<script>" hub/extensions/ --include="*.html" --include="*.tsx"

# Check for SQL string concatenation
grep -r "fmt.Sprintf.*INSERT\|fmt.Sprintf.*SELECT\|fmt.Sprintf.*DELETE" core/ --include="*.go"

# Check for unsafe CSP patterns
grep -r "unsafe-inline\|unsafe-eval" hub/ --include="*.ts" --include="*.tsx"
```

### Step 3: Update .env

```bash
# Verify secret strength
python3 -c "
import os
with open('.env') as f:
    for line in f:
        if '=' in line:
            k, v = line.strip().split('=', 1)
            if k in ('RENOS_JWT_SECRET', 'RENOS_ENCRYPTION_KEY'):
                assert len(v) >= 32, f'{k} is too short ({len(v)} chars)'
print('All secrets meet length requirements')
"

# Generate new secrets if needed
if [ ${#RENOS_JWT_SECRET} -lt 32 ]; then
  echo "RENOS_JWT_SECRET=$(openssl rand -base64 48)" >> .env
fi
if [ ${#RENOS_ENCRYPTION_KEY} -lt 32 ]; then
  echo "RENOS_ENCRYPTION_KEY=$(openssl rand -base64 48)" >> .env
fi
```

### Step 4: Fix webhook scripts

Replace SQL string concatenation with parameterized queries in all
webhook handler scripts:

```go
// Before (v0.3.0) — will be blocked
payload := r.FormValue("payload")
query := fmt.Sprintf("INSERT INTO logs (data) VALUES ('%s')", payload)

// After (v1.0.0)
var payload map[string]any
json.NewDecoder(r.Body).Decode(&payload)
query := "INSERT INTO logs (data) VALUES ($1)"
db.Exec(query, json.Marshal(payload))
```

### Step 5: Fix terminal/plugin token generation

```go
// Before
token := fmt.Sprintf("%x", rand.Uint64())

// After
b := make([]byte, 32)
if _, err := crypto/rand.Read(b); err != nil {
    return "", err
}
token := hex.EncodeToString(b)
```

### Step 6: Update hub extensions

Move inline scripts to separate files and update CSP:

```tsx
// Before
<script>console.log('hello')</script>

// After — use Next.js Script component with strategy
import Script from 'next/script'
<Script src="/plugins/my-plugin/script.js" strategy="afterInteractive" />
```

### Step 7: Pull new images and migrate

```bash
docker compose -f docker-compose.prod.yml pull

# Start infrastructure
docker compose up -d postgres redis nats

# Run migrations
cd core && go run ./cmd/renos-core/ migrate

# Start all services
docker compose -f docker-compose.prod.yml up -d
```

### Step 8: Update agent config

On each agent, update to allowlist any custom commands needed:

```bash
# /etc/renos/agent.conf
# Add any legit commands that might be blocked
command_allowlist = "/usr/local/bin/deploy.sh,/opt/renos/scripts/*"
```

### Step 9: Re-test all integrations

```bash
# Test webhook scripts
renctl webhooks test --all

# Test plugin endpoints
renos plugins:test --all

# Test workflow execution
renos workflows:test --all

# Test terminal sessions
renos terminal test --device all --command "uptime"
```

## Rollback Procedure

```bash
# 1. Stop all services
docker compose -f docker-compose.prod.yml down

# 2. Restore pre-upgrade database
./scripts/restore.sh backups/renos-backup-<pre-upgrade-date>.sql.gz

# 3. Restore configuration
cp .env.v0.3.0 .env

# 4. Restore v0.3.0 Docker images
docker compose -f docker-compose.prod.yml pull renos-core:0.3.0
# Edit docker-compose.prod.yml to pin image tags to :0.3.0

# 5. Restart
docker compose -f docker-compose.prod.yml up -d

# 6. Verify rollback
curl http://localhost:8443/api/v1/version
# Expected: {"version":"0.3.x"}
```

## Verification

```bash
echo "=== v1.0.0 Upgrade Verification ==="

echo "1. Health check"
curl -f http://localhost:8443/api/v1/healthz || exit 1
echo "   PASS"

echo "2. Readiness check"
curl -f http://localhost:8443/api/v1/readyz || exit 1
echo "   PASS"

echo "3. Version"
VERSION=$(curl -s http://localhost:8443/api/v1/version | jq -r '.data.version')
[ "$VERSION" = "1.0.0" ] || [ "$VERSION" = "1.0.0-rc2" ] || { echo "   FAIL: version mismatch"; exit 1; }
echo "   PASS ($VERSION)"

echo "4. Authentication"
TOKEN=$(curl -s -X POST http://localhost:8443/api/v1/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"email":"admin@renos.local","password":"admin"}' | jq -r '.token')
[ -n "$TOKEN" ] && [ ${#TOKEN} -gt 20 ] || { echo "   FAIL: no token"; exit 1; }
echo "   PASS"

echo "5. CSRF protection"
STATUS=$(curl -s -o /dev/null -w "%{http_code}" -X POST http://localhost:8443/api/v1/devices/abc/commands \
  -H 'Content-Type: application/json' \
  -d '{"command":"uptime"}')
[ "$STATUS" = "401" ] || [ "$STATUS" = "403" ] || { echo "   FAIL: expected 401/403, got $STATUS"; exit 1; }
echo "   PASS (CSRF blocks unauthenticated requests)"

echo "6. Pagination limits enforced"
STATUS=$(curl -s -o /dev/null -w "%{http_code}" \
  -H "Authorization: Bearer $TOKEN" \
  "http://localhost:8443/api/v1/devices?page=1&per_page=500")
[ "$STATUS" = "400" ] || { echo "   FAIL: expected 400, got $STATUS"; exit 1; }
echo "   PASS (per_page > 200 blocked)"

echo "7. Error sanitization"
ERROR=$(curl -s -H "Authorization: Bearer $TOKEN" \
  "http://localhost:8443/api/v1/devices/nonexistent" | jq -r '.message')
[[ "$ERROR" != *"/go/src/"* ]] || { echo "   FAIL: internal path leaked"; exit 1; }
echo "   PASS (no path leakage)"

echo "8. CSP headers"
CSP=$(curl -s -I http://localhost:8443 | grep -i content-security-policy)
[[ "$CSP" != *"unsafe-inline"* ]] || { echo "   FAIL: CSP allows unsafe-inline"; exit 1; }
echo "   PASS (CSP hardened)"

echo "9. Security headers"
curl -s -I http://localhost:8443 | grep -qi "x-frame-options: DENY" || { echo "   FAIL: missing X-Frame-Options"; exit 1; }
curl -s -I http://localhost:8443 | grep -qi "x-content-type-options: nosniff" || { echo "   FAIL: missing X-Content-Type-Options"; exit 1; }
echo "   PASS"

echo "10. Device listing"
COUNT=$(curl -s -H "Authorization: Bearer $TOKEN" \
  "http://localhost:8443/api/v1/devices?page=1&per_page=10" | jq '.total')
echo "   Devices: $COUNT"
echo "   PASS"

echo ""
echo "=== All checks passed ==="
```

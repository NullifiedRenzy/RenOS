# Upgrade: v0.1.0 → v0.2.0

**Release date:** 2026-04-15

## Summary

v0.2.0 introduces the RenFlow automation engine, the first stable Plugin
API (v1), a new authentication system with JWT-based sessions, and the
initial device enrollment workflow.

## Breaking Changes

### 1. Authentication: API Key → JWT Token

v0.1.0 used static API keys passed via `X-API-Key` header. v0.2.0 replaces
this with JWT-based authentication.

**Before (v0.1.0):**
```bash
curl -H "X-API-Key: your-static-key" http://localhost:8443/api/v1/devices
```

**After (v0.2.0):**
```bash
TOKEN=$(curl -s -X POST http://localhost:8443/api/v1/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"email":"admin@renos.local","password":"admin"}' | jq -r '.token')
curl -H "Authorization: Bearer $TOKEN" http://localhost:8443/api/v1/devices
```

### 2. Plugin API: v0 (provisional) → v1 (stable)

The plugin manifest format changed. The `capabilities` field was replaced
with `permissions`, and routes are now declared explicitly.

**Before (v0.1.0):**
```json
{
  "name": "my-plugin",
  "version": "0.1.0",
  "capabilities": ["read_devices", "exec_commands"]
}
```

**After (v0.2.0):**
```json
{
  "name": "my-plugin",
  "type": "wasm",
  "version": "1.0.0",
  "permissions": ["devices:read", "devices:exec:local"],
  "routes": [
    {
      "path": "/api/v1/plugins/my-plugin/action",
      "method": "GET",
      "description": "My action"
    }
  ]
}
```

### 3. Workflow format: Flat → DAG-based

The beta workflow format in v0.1.0 used a simple sequential step list.
v0.2.0 introduces the RenFlow DAG engine with triggers, conditions,
variables, and error handling.

### 4. Configuration: Environment file changes

New required variables were added and some were renamed.

**Removed:**
- `RENOS_API_KEY` (replaced by JWT auth)

**New required:**
- `RENOS_JWT_SECRET` (min 32 characters)
- `RENOS_ENCRYPTION_KEY` (min 32 characters)
- `RENOS_NATS_URL` (NATS server for internal bus)

**Renamed:**
- `RENOS_DB_URL` → `RENOS_DATABASE_URL`

## Step-by-Step Migration

### Step 1: Backup

```bash
./scripts/backup.sh
cp .env .env.v0.1.0
cp /etc/renos/ca /etc/renos/ca.v0.1.0 -r
```

### Step 2: Update .env

```bash
# Add new required variables
echo "RENOS_JWT_SECRET=$(openssl rand -base64 48)" >> .env
echo "RENOS_ENCRYPTION_KEY=$(openssl rand -base64 48)" >> .env
echo "RENOS_NATS_URL=nats://localhost:4222" >> .env

# Rename old DB variable
sed -i 's/RENOS_DB_URL/RENOS_DATABASE_URL/' .env
```

### Step 3: Stop services

```bash
docker compose -f docker-compose.prod.yml down
```

### Step 4: Run database migration

```bash
docker compose up -d postgres redis nats
cd core && go run ./cmd/renos-core/ migrate
```

### Step 5: Generate enrollment tokens

```bash
docker compose up -d
./renctl enroll-token create --label "migration-upgrade" --expires-in 24h
```

Existing agents will need to re-enroll using the new token.

### Step 6: Re-enroll agents

On each managed device:

```bash
# Update agent config
sudo sed -i 's/api_key=.*/token=<new-enrollment-token>/' /etc/renos/agent.conf
sudo systemctl restart renos-agent
```

### Step 7: Update plugins

Reinstall any v0.1.0 plugins with the new manifest format:

```bash
renos plugins:uninstall my-plugin
renos plugins:install ./my-plugin/plugin.json
renos plugins:enable my-plugin
```

## Database Migration

| Migration ID | Description |
|---|---|
| `002_add_users_table` | Creates `users` table with roles and password hashes |
| `003_add_jwt_sessions` | Creates `sessions` table for JWT token tracking |
| `004_add_workflows` | Creates `workflows` and `workflow_runs` tables (RenFlow) |
| `005_add_plugin_system` | Creates `plugins` table with permissions model |
| `006_add_device_enrollment` | Adds enrollment flow columns to `devices` table |
| `007_rename_api_keys` | Migrates API keys to user-bound tokens |

## Rollback Procedure

```bash
# Stop services
docker compose -f docker-compose.prod.yml down

# Restore database from backup
./scripts/restore.sh backups/renos-backup-<pre-upgrade-date>.sql.gz

# Restore configuration
cp .env.v0.1.0 .env
cp /etc/renos/ca.v0.1.0 /etc/renos/ca -r

# Restore v0.1.0 images
docker compose -f docker-compose.prod.yml up -d
```

## Verification

```bash
# Check auth system
curl -s -X POST http://localhost:8443/api/v1/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"email":"admin@renos.local","password":"admin"}' | jq .
# Expected: {"token":"eyJ...","user_id":"...","expires_at":"..."}

# Check devices still registered
TOKEN=$(curl -s ... | jq -r '.token')
curl -s -H "Authorization: Bearer $TOKEN" http://localhost:8443/api/v1/devices | jq '.total'
# Expected: same count as before upgrade

# Check plugin system
curl -s -H "Authorization: Bearer $TOKEN" http://localhost:8443/api/v1/plugins | jq .
# Expected: list of installed plugins

# Test workflow engine
curl -s -H "Authorization: Bearer $TOKEN" http://localhost:8443/api/v1/workflows | jq .
# Expected: empty list or existing workflows

# Check NATS connection
docker compose exec nats nats server check --expected=1
# Expected: "OK"
```
